# Task: 活动历史持久化与用时统计

## 描述
实现 ActivityStore 服务和 StatsView 视图。ActivityStore 在 FileWatcher 检测到状态变更时，对比内存快照生成 ActivityEvent，持久化到 ~/.piq/activity.json。StatsView 基于活动历史计算 task 耗时、epic 耗时和项目吞吐量。ActivityFeedView 在主面板中展示最近活动时间线。

## 验收标准
- [ ] ActivityStore 维护内存中的状态快照（上次各文件的 status 值）
- [ ] 文件状态变更时生成 ActivityEvent（包含 oldStatus → newStatus）
- [ ] 新文件出现时生成创建事件（oldStatus = nil）
- [ ] 活动事件追加写入 ~/.piq/activity.json
- [ ] App 重启后从 JSON 文件恢复历史
- [ ] ActivityFeedView 在主面板中展示最近 20 条活动，格式："5m ago Task #42 → in-progress"
- [ ] StatsView 统计面板：task 平均耗时、epic 总耗时、每日/每周完成量
- [ ] 活动历史文件损坏时自动重建（清空历史，从当前状态重新开始）
- [ ] 数据管理：可配置保留天数，可导出 JSON/CSV

## 技术细节
- ActivityStore.swift：
  - statusSnapshot: [String: ItemStatus]（key 为文件路径）
  - onFileChanged(path, newItem)：对比 snapshot，生成 event，更新 snapshot
  - 持久化：每次写入都 append 到 JSON array，启动时一次性 load
  - 考虑写入性能：batch write（累积 5 秒或 10 个事件后批量写入）
- ActivityFeedView.swift：
  - 显示最近 N 条事件
  - 时间显示为相对时间（"5m ago"、"1h ago"、"3d ago"）
  - 按时间倒序排列
- StatsView.swift：
  - 计算 task 生命周期：open→in-progress 时间 + in-progress→done 时间
  - 计算 epic 总耗时
  - 简单的 bar chart 或数字统计展示
